## 1. 三个方向总览

三个方向在**构图、密度、封面角色、色彩策略、信息节奏**五个维度上刻意拉开差距，不是换主题色。

### 方向 A — 报刊信息卡（Press Card）

- **设计命题**：把海报做成一张"印刷出来的视频信息卡"。报头眉线、墨黑文字、纸色底、表格化统计，强调数据快照的可信感与信息密度。
- **构图**：封面作为顶部横幅（16:9 居中裁切）被信息区框住；标题、UP 主 + BV/AV、统计四格表、底部二维码 + 链接依次纵向排布，信息全部"落位"在网格上。
- **密度**：高。一屏容纳全部 9 项内容，适合内容密集的分享场景。
- **封面角色**：横幅装饰 + 视觉锚点，不承载文字，任何横向封面裁切都不会破坏文字可读性。
- **色彩策略**：纸白 `#F7F5F0` + 墨黑 `#1A1A1A` + 灰；无彩色点缀，黑白印刷感。导出后脱离 Bilibili 环境依然自解释，且与官方深色弹层距离最远。
- **宽高比**：3:4（导出基准 1080×1440）。
- **主要取舍**：牺牲"视觉冲击力"换取"信息可信度与普适性"；封面被框住，无法像电影海报那样全出血。

### 方向 B — 沉浸封面（Cinematic）

- **设计命题**：海报即封面。像电影海报一样让封面全出血铺满整张图，文字浮在深色渐变遮罩上。
- **构图**：封面 = 整张海报背景；标题底部居中，UP 主紧随，统计压缩成底部一条毛玻璃数据条，二维码 + 链接收进右下角白卡。
- **密度**：低–中。靠留白与对比建立层级，信息量不变但节奏更戏剧化。
- **封面角色**：唯一主角。封面质量直接决定海报成败。
- **色彩策略**：深色遮罩 + 封面取色，文字白色。亮色封面上同样成立（遮罩保证对比度）。
- **宽高比**：9:16（导出基准 1080×1920），竖屏分享（朋友圈/抖音外链）观感最佳。
- **主要取舍**：最"好看"但也最依赖封面；封面暗部或花哨时遮罩必须加重，信息辨识度风险最高；文字（尤其长标题）可承载行数最少。

### 方向 C — B站亲和（Bili Native）

- **设计命题**：借用 Bilibili 页面环境的熟悉感——粉色 `#FB7299`、圆角卡片、浅灰底、胶囊标签，让海报"看起来就属于 B 站"，与官方分享弹层同族但内容更完整。
- **构图**：封面圆角卡片置顶（角标挂分P/时间），下方标题卡、统计条、底部二维码 + 链接 + BV/AV 三行分区；每个信息块是独立卡片。
- **密度**：中。分区清晰，扫读快。
- **封面角色**：内容卡之一，被圆角与角标"产品化"。
- **色彩策略**：亮色：白底 + 粉主色 + 灰层级；链接用 B 站蓝 `#00AEEC`。与官方视觉最近，但"分享海报"身份靠报头式标题与导出动作区分。
- **宽高比**：3:4（导出基准 1080×1440）。
- **主要取舍**：辨识度最高、学习成本最低，但与官方弹层视觉距离最近，容易被误读为官方功能；亮色在浅色页面环境下对比度不如 A/B 突出。

### 快速对比表

| 维度 | A 报刊信息卡 | B 沉浸封面 | C B站亲和 |
|---|---|---|---|
| 宽高比（导出） | 3:4 · 1080×1440 | 9:16 · 1080×1920 | 3:4 · 1080×1440 |
| 构图 | 横幅+纵向网格 | 全出血+浮层 | 圆角卡片分区 |
| 信息密度 | 高 | 低–中 | 中 |
| 封面角色 | 横幅（被框住） | 整图背景（全出血） | 圆角内容卡 |
| 色彩策略 | 纸白+墨黑（无彩色） | 深色遮罩+封面取色 | 白+粉+蓝（B站同族） |
| 与官方视觉距离 | 最远 | 远 | 最近 |
| 数据可读性 | 最强（表格化） | 依赖遮罩 | 强（分区化） |

## 2. 页面入口（三方向共用位置，样式随方向）

位置：Bilibili 官方分享按钮**右侧**（交接文档要求）。原型中模拟了视频标题行下的操作区（点赞/投币/收藏/官方分享/新入口）。

- **A**：白底细边框墨字按钮 `🖼 生成海报`——克制、印刷感，与灰色官方分享按钮并列不抢戏。
- **B**：深色实心按钮 + 图片图标 `生成海报`——与沉浸海报气质一致，明暗上从官方灰按钮中跳出。
- **C**：粉色胶囊按钮 + 图片图标 `生成海报`——与 B 站主色一致，但用"海报"图标+文案明确表达"生成分享海报"，避免被误读为重复官方分享。

防混淆手段（三个方向通用）：① 图标用**图片/海报**而非分享箭头；② 文案为动词短语"生成海报"而非名词"分享"；③ 入口与官方分享按钮之间有间距且样式可区分。Tampermonkey 菜单入口是备用能力，无视觉稿要求。

## 3. 分享面板设计（每方向配套）

| 设计点 | A 报刊信息卡 | B 沉浸封面 | C B站亲和 |
|---|---|---|---|
| 形态 | 900px 分栏面板：左海报预览（46%）右控制区（54%） | 760px 暗色弹层：海报大图居中，控制条在下方 | 860px 浅色弹层：左预览右控制，卡片分区 |
| 选项 | 四宫格开关（分P/时间戳/详细文案/Markdown），带"默认关"副标签 | 胶囊 chips（开=粉色高亮） | 两列选项卡片，与 A 同构但更圆润 |
| 文案区 | 等宽字体预览框，位于选项下方、导出上方，精确呈现 | 暗色代码风格预览框，位于控制条下方 | 预览框位于右侧控制区中部 |
| 导出 | 主按钮"复制海报"（粉）+"下载 PNG"+"复制文案"+"组合复制"，一行排布 | 同四动作，主按钮粉色实心、其余暗色 | 同四动作，主按钮粉色 |
| 状态反馈 | 降级提示条（琥珀色）在海报与文案之间；重建时导出禁用+预览遮罩"正在更新…"；关闭提示与复制失败引导文字在底部 | 降级提示条在预览与控制条之间；重建遮罩为深色半透明 | 降级提示条在标题下方通栏；重建遮罩+导出禁用 |
| 关闭 | ✕ / Esc / 点击遮罩（三方向统一，符合 idea.md） | 同左 | 同左 |
| 窄视口（<760px） | 分栏折叠为纵向：预览在上、控制在下 | 弹层收窄，海报缩小，控制条换行 | 分栏折叠为纵向 |

**诚实反馈**（三方向统一文案）：
- 组合复制：界面明确写"组合复制（图+文）"且底部注明"组合复制写入兼容格式，接收方可能只取其中一种；复制失败时引导下载 PNG"——不承诺先图后文。
- 复制失败：面板保持可用并引导"下载 PNG"，不自动触发下载（符合 idea.md）。
- 更新中：旧预览保留但覆盖"正在更新…"遮罩，导出按钮全部 `disabled`（符合 idea.md 的 updating placeholder 规则）。

## 4. 海报排版决策（三方向共同立场）

- **信息层级**：封面 → 标题 → UP 主/标识 → 统计 → 二维码+链接。BV/AV 与二维码+链接**同一落点**（二维码旁固定出现可见链接），保证"扫码"与"看链"互为备份。
- **封面裁切**：三方向均用 `object-fit: cover` 居中裁切 16:9 横向封面；A/C 裁进横幅/圆角卡，B 全出血。设计不依赖封面内容，任意横向封面成立（原型封面为标注的占位图）。
- **数字呈现**：`font-variant-numeric: tabular-nums` 等宽数字；播放/点赞/投币/收藏在 A 用 `万` 紧凑（12,345,678 → 1234.6万，-- 保留原样），B/C 同策略；详细文案始终显示精确值带千分位（符合 idea.md 第 87 行）。
- **字体**：系统中文栈 `PingFang SC / Microsoft YaHei`；链接与 BV/AV 用等宽栈 `ui-monospace/Menlo`；标题/UP 主保持原文，不翻译不改写。
- **二维码**：白底 + 四周留白安静区（原型用带白色内边距的 70–78px 方块）；二维码与链接使用同一 share target（符合 idea.md）。原型中的二维码是**视觉示意**（伪码图案并标注"示例QR"），真实可扫描性验证属于独立技术原型。
- **长链接降级排版**：`word-break: break-all` 允许长链换行，等宽小字号；场景 4 已验证 `https://www.bilibili.com/video/BV1xx411c7mD/?p=2&t=3723` 三方向均完整可见不溢出。
- **分P/时间**：仅在启用时出现。A 用墨黑小胶囊+时间右对齐；B 用顶部毛玻璃胶囊；C 用封面右下角胶囊。仅 `P2` 无标题时胶囊只显示 `P2`（符合 idea.md 第 82 行）。

## 5. 压力与状态场景验证结果

原型五个场景（浮动条切换）逐一验证：

| 场景 | 验证内容 | A 报刊信息卡 | B 沉浸封面 | C B站亲和 |
|---|---|---|---|---|
| 1 默认 | 默认落点、简洁文案、生成完成 | ✅ 全部字段落位 | ✅ 底部信息条完整 | ✅ 卡片分区完整 |
| 2 多分P详细 | P2·分P标题、01:02:03、详细文案、Markdown | ✅ 胶囊+时间行不挤压标题 | ✅ 顶部胶囊+时间，标题 3 行空间够 | ✅ 封面角标，正文不受影响 |
| 3 更新中 | 旧预览+重建遮罩+导出禁用 | ✅ 遮罩盖住整卡，按钮 disabled | ✅ 深色遮罩+禁用 | ✅ 遮罩+禁用 |
| 4 短链降级 | 长链接三处同源、排版完整 | ✅ 链接两行换行不溢出 | ✅ 白卡内两行换行，字号最小但完整 | ✅ 链接换行完整 |
| 5 压力内容 | 超长【】标题、长UP名、`--` 统计、仅 `P2` 无分P标题 | ✅ 标题 2 行省略+UP 名截断安全，`--` 显示 | ⚠️ 长标题占 3 行上限，**最长标题将接近边界**；UP 名在标题下完整显示 | ✅ 标题 2 行省略，`--` 显示 |

**失效点与调整建议**：
- **B 是压力风险最高的方向**：超长标题（约 24 字）在 19px/3 行上限下接近极限，若标题更长需降字号或压缩统计条；UP 主名与统计条叠加在深色遮罩上，遮罩透明度需保持 ≥86% 底端值。**建议**：B 采用"标题字号随长度阶梯降级（19→17→15px）"规则。
- **A 的链接区最窄**：短链无压力，但长链在两行内换行后视觉略碎；**建议**：长链降级时允许链接区占满整行宽（二维码上移或并排缩小）。
- **C 无失效点**，但亮色海报在暗色页面环境（Bilibili 深色模式）中面板与海报对比强烈，属预期而非缺陷。
- **缺失统计 `--`**：三方向均正确显示，不伪装为 0（符合 idea.md 第 39 行）。

**亮/暗页面环境**：A/C 海报本身为亮色，在暗色页面上以白色面板承载，边界清晰；B 海报深色，在暗色页面上融入感强、亮色页面反差大。**是否给海报提供多主题（亮/暗变体）是留给所有者选择的设计决策**（见 §7 Q3）。

## 6. 二维码可扫描性、层级、对比度与导出自解释性

- **可扫描性**：三方向二维码均为白底、≥4 模块的安静区、70–78px 显示尺寸（导出 1080 基准下对应约 240–260px 物理尺寸，远超可扫描下限）；二维码**不叠放在封面或其他图形之上**（A/C 独立落点、B 独立白卡），不设半透明或圆角裁切二维码。真实可扫描验证（含 b23.tv 跳转保真）留给技术原型。
- **层级**：二维码始终是底部"行动区"的主角，链接紧随其后；分P/时间胶囊与二维码分离，避免扫描干扰。
- **对比度**：二维码固定黑/白两色，不随方向主题变色；A/C 纸白/纯白底，B 白卡底，满足 ≥4.5:1 的常规要求。
- **导出后自解释**：A 有"BILIBILI 分享海报"报头、C 有 B 站视觉语言、B 有封面+白卡；三方向导出后即使脱离页面，观看者都能看出"这是一个 B 站视频的分享图"，且链接/BV/AV 三重身份可定位视频。

## 7. 推荐方向与待所有者选择的问题

### 推荐：方向 A — 报刊信息卡（备选 C）

**理由**：
1. **信息优先**：本产品核心价值是"信息丰富的分享图"（idea.md problem statement）。A 的表格化统计、网格落位是所有方向中数据可读性最强、长标题与长链接最稳的——压力验证零失效。
2. **自解释与独立身份**：纸感报头与官方深色弹层距离最远，不会与官方分享混淆，导出后"信息卡"身份一目了然。
3. **风险最低**：不依赖封面质量（B 的硬伤），不贴近官方（C 的混淆风险），裁剪、缺失统计、降级链接等所有边界都有明确排版位置。
4. **技术友好**：3:4 固定网格对 PNG 导出与组合剪贴板的排版引擎最可预测。

**为什么不是 C**：C 是优秀的备选，辨识度与社区感最佳，但与官方视觉过近，且亮色卡片在暗色页面环境下不如 A 的纸感有边界。若所有者更看重"看起来属于 B 站"，选 C 完全合理。

### 需要所有者最终选择的少量问题

1. **方向**：A / B / C / 混合（如"B 的封面全出血 + A 的表格统计"），请指定方向或组合。当前所有者选择"暂不定，混合摘取"，本原型保持三方向并排以便摘取。
2. ~~**海报主题**~~：已决——单主题，保持简单，不提供亮/暗变体。
3. **宽高比**：A/C 按 3:4（1080×1440）、B 按 9:16（1080×1920）设计；是否需要 1:1 社交网格变体？
4. **数字紧凑精度**：A 采用"一位小数万/亿"（1234.6万）；是否接受向下取整（1234万）以更短？
5. **入口文案**："生成海报" vs "分享海报"——交接文档要求表达"生成分享海报"；本原型用"生成海报"，若主人偏好"分享海报"可全局替换。
