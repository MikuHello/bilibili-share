# Bilibili 分享海报 · 视觉系统 spec

Status: approved（2026-08-14；视觉部分；产品其余行为仍由 `.scratch/bilibili-share-poster/idea.md` 约束）

> 范围声明：本 spec 仅覆盖**视觉系统**（分享海报、分享面板、页面入口的视觉与布局），由视觉探索定稿合成。userscript 的运行时行为、数据获取、剪贴板等仍以 `idea.md` 为单一事实源，不在本 spec 重复授权。

## Problem Statement

Bilibili Web 官方分享动作不提供信息丰富的分享图。视觉方向已经过探索与定稿：海报需要同时承载封面、标题、UP 主、BV/AV、数据快照、二维码与可见链接，并在多种内容压力（长标题、长链接、缺失统计、多分P）下保持可读、可扫描、导出后自解释。此前缺少一份把视觉决策固定下来的规格，导致实现阶段无法确定海报尺寸、主题、排版与面板布局。

## Solution

一套由 **A 报刊信息卡** 与 **B 沉浸封面** 两种可选主题构成的分享海报视觉系统（C B站亲和不采用），配套分享面板与页面入口。所有主题共用同一份信息模型与字段层级：封面 → 标题 → UP 主/标识 → 统计 → 二维码+链接；数字使用一位小数万/亿紧凑格式；二维码与可见链接同一落点、同一 share target。分享面板提供海报预览、四种选项（分P/时间戳/详细文案/Markdown）、四种导出动作（复制海报/下载 PNG/复制文案/组合复制）与诚实的状态反馈。

## User Stories

1. As a Bilibili 视频观看者, I want 在官方分享按钮右侧看到"生成海报"入口, so that 我知道这是生成分享海报而不是重复官方分享。
2. As a Bilibili 视频观看者, I want 入口按钮带海报/图片图标和动词短语"生成海报", so that 不会被误读为官方分享。
3. As a Bilibili 视频观看者, I want 点击入口后打开分享面板, so that 我可以预览海报与文案并选择导出方式。
4. As a Bilibili 视频观看者, I want 面板内海报预览与导出一致, so that 我导出前看到的就是最终产物。
5. As a Bilibili 视频观看者, I want 海报显示视频封面, so that 看图的人能立即识别视频。
6. As a Bilibili 视频观看者, I want 海报显示完整视频标题（最多 2–3 行省略）, so that 长标题不破坏布局且不失义。
7. As a Bilibili 视频观看者, I want 海报显示 UP 主名称, so that 归属可见。
8. As a Bilibili 视频观看者, I want BV 与 AV 标识同时可见, so that 两种检索方式都可用。
9. As a Bilibili 视频观看者, I want 海报显示播放/点赞/投币/收藏快照, so that 分享图自带数据上下文。
10. As a Bilibili 视频观看者, I want 统计数字使用一位小数万/亿紧凑格式, so that 数字可读且不改变数据含义。
11. As a Bilibili 视频观看者, I want 缺失的单个统计显示为 `--`, so that 不会误读为零。
12. As a Bilibili 视频观看者, I want 海报二维码可可靠扫描且与可见链接指向同一 share target, so that 扫码与看链互为备份。
13. As a Bilibili 视频观看者, I want 二维码有白底与安静区且不与封面叠加, so that 任何背景上都能扫描。
14. As a Bilibili 视频观看者, I want 二维码旁可见完整分享链接, so that 无法扫码时也能打开。
15. As a Bilibili 视频观看者, I want 长链接在窄栏内可换行完整显示, so that 短链降级时链接仍可用。
16. As a Bilibili 视频观看者, I want 启用分P时海报显示 `P<number> · <分P标题>`, so that 看图的人知道是第几P。
17. As a Bilibili 视频观看者, I want 分P标题缺失时只显示 `P<number>`, so that 不发明占位标题。
18. As a Bilibili 视频观看者, I want 启用时间戳时海报显示当前播放位置时间, so that 分享的是该时间点的观看入口。
19. As a Bilibili 视频观看者, I want 未启用分P/时间戳时海报不显示相关标签, so that 默认海报干净。
20. As a Bilibili 视频观看者, I want 海报支持 A 报刊信息卡与 B 沉浸封面两种主题, so that 我可以选择信息密度或视觉冲击。
21. As a Bilibili 视频观看者, I want A 主题为亮色纸感、高密度、表格化统计, so that 数据可读性最强。
22. As a Bilibili 视频观看者, I want B 主题为深色封面全出血、低密度、毛玻璃数据条, so that 视觉冲击最强。
23. As a Bilibili 视频观看者, I want 两种主题共用同一信息层级与字段集合, so that 切换主题不改变内容语义。
24. As a Bilibili 视频观看者, I want 主题选择记住上次使用结果, so that 下次打开分享面板时无需重复切换。
25. As a Bilibili 视频观看者, I want 海报导出为 3:4（1080×1440）PNG, so that 符合社交分享常见比例。
26. As a Bilibili 视频观看者, I want 封面按 16:9 居中裁切, so that 任意横向封面都能成立。
27. As a Bilibili 视频观看者, I want 海报脱离页面后仍自解释（含品牌识别与身份信息）, so that 接收者不需要页面上下文。
28. As a Bilibili 视频观看者, I want 面板内可开关分P分享、时间戳、详细文案、Markdown 四项选项, so that 我能组合出想要的分享形态。
29. As a Bilibili 视频观看者, I want 面板显示分享文案精确预览, so that 复制前知道内容。
30. As a Bilibili 视频观看者, I want 面板提供复制海报（主）、下载 PNG、复制文案、组合复制四个动作, so that 覆盖所有导出路径。
31. As a Bilibili 视频观看者, I want 选项变更触发重建时旧预览仍可见但导出锁定, so that 我知道正在更新且不会导出不一致内容。
32. As a Bilibili 视频观看者, I want 短链降级时面板明确提示并展示长链接, so that 我知道发生了什么。
33. As a Bilibili 视频观看者, I want 组合复制反馈诚实描述"写入兼容格式", so that 我不被误导为所有目标都会先图后文。
34. As a Bilibili 视频观看者, I want 复制失败时面板保持可用并引导下载 PNG, so that 有替代路径。
35. As a Bilibili 视频观看者, I want 面板可通过 ✕、Esc、点击遮罩关闭, so that 关闭方式符合习惯。
36. As a Bilibili 视频观看者, I want 窄视口下面板自适应为纵向布局, so that 小窗口也可用。
37. As a Bilibili 视频观看者, I want 所有界面文案为简体中文且标题/UP 主保持原文, so that 语言一致且尊重原内容。

## Implementation Decisions

以下决策来自视觉探索（`design/prototype.html` 与 `design/visual-directions.md`），经项目所有者定稿。

### 海报尺寸与画布

- 导出基准 **1080×1440（3:4）**，两种主题共用同一画布比例（B 主题在 3:4 下成立，不再使用 9:16）。
- 封面按 16:9 横向、`cover` 居中裁切：A 主题裁入顶部横幅，B 主题全出血铺底。
- 布局使用固定网格/留白系统，不依赖封面内容位置。

### 主题 A — 报刊信息卡（默认）

- 纸色底 `#F7F5F0` + 墨黑文字 `#1A1A1A` + 灰阶辅助 `#6B6B66`；无彩色点缀，印刷感。
- 结构自上而下：报头眉线（BILIBILI 分享海报 + SHARE CARD）→ 封面横幅（细边框）→ 标题（19px 显示级，最多 2 行省略）→ UP 主 + BV/AV 一行 → 分P胶囊/时间（条件出现）→ 四格统计表（2px 顶线分隔）→ 底部二维码+链接区。
- 统计为表格化四列，数字 `tabular-nums` 16px 加粗，标签 9px 字距拉开。
- 二维码 78px 白底方框，链接区等宽字体 `word-break: break-all`。

### 主题 B — 沉浸封面（可选）

- 封面全出血 + 底部渐变遮罩（38% 处 28% 黑 → 78% 处 86% 黑 → 94% 处 94% 黑），文字白色。
- 结构：顶部毛玻璃胶囊（分P/时间，条件出现）→ 底部标题（最多 3 行，字号 19px，随长度阶梯降级 19→17→15px）→ UP 主 → 毛玻璃数据条（四个统计横排）→ BV/AV → 白卡二维码（72px）+ 链接。
- 二维码独立白卡，不叠封面；遮罩底端透明度 ≥86% 保证文字对比度。

### 主题选择

- A 报刊信息卡为首次使用的默认主题。
- 用户切换 A/B 主题后记住上次选择；下次打开分享面板时恢复该主题。
- 切换主题只改变视觉表现，不改变 generation snapshot、字段集合或 share target。

### 数字呈现

- 统计数字使用**一位小数万/亿**紧凑格式（`12,345,678 → 1234.6万`，`--` 原样保留）；详细 share text 仍显示精确千分位值（由 idea.md 约束，不在本 spec 改变）。
- 时间显示：低于一小时 `MM:SS`，一小时及以上 `HH:MM:SS`（沿用 idea.md）。

### 二维码与链接

- 二维码与可见链接使用同一 share target；二维码固定黑白两色、白底、保留安静区，不随主题变色。
- 短链默认 `b23.tv`；降级时海报、二维码、文案统一使用规范长链接，面板出现降级提示。
- 原型中的二维码为视觉示意图案；**真实可扫描验证属独立技术原型**，本 spec 只固定排版与对比度规则。

### 分享面板

- 面板形态（两种主题共用一套面板，视觉随主题微调）：
  - A 主题：浅色分栏面板，左海报预览（46%）右控制区（54%）；窄视口折叠为纵向。
  - B 主题：深色弹层，海报居中、控制条在下方；窄视口收窄换行。
- 控件层级：标题 → 选项（分P/时间戳/详细文案/Markdown）→ 文案预览（等宽字体，精确呈现）→ 导出行（复制海报为主按钮）→ 状态/说明文字。
- 状态反馈位置：降级提示在预览与文案之间（琥珀色条）；重建时预览覆盖"正在更新…"遮罩且导出按钮 `disabled`；复制失败提示在说明区，引导下载 PNG。
- 组合复制文案诚实表述"写入兼容格式，接收方可能只取其中一种"。

### 页面入口

- 位于官方分享按钮右侧；图标用海报/图片（非分享箭头），文案"生成海报"。
- 样式随主题：A 白底墨字细边框按钮；B 深色实心按钮。与官方灰色分享按钮间距与样式可区分。
- Tampermonkey 菜单入口为备用能力，无视觉稿要求。

### 字体与语言

- 系统中文栈 `PingFang SC / Microsoft YaHei`；链接与 BV/AV 用等宽栈 `ui-monospace/Menlo`。
- 界面简体中文；视频标题与 UP 主名保持原文。
- 标题省略：A/C 2 行、B 3 行，行尾省略不截断语义（`【】` 保持原样）。

### 测试 seam（已与所有者确认）

- **单一 seam：领域核心与浏览器副作用之间**。
- seam 一侧：视觉决策中的纯逻辑（数字紧凑化、时间格式化、字段层级组装、主题选择、链接换行规则、标题行数规则）为纯 TS 模块，可在 Node 中测试。
- seam 另一侧：DOM 渲染、Tampermonkey 注入、网络、剪贴板为薄适配器，不做单元测试，由集成/手动验证。
- 海报渲染本身（HTML→PNG）不进入 seam 的单元测试范围，其正确性由原型与视觉验收验证。

## Testing Decisions

- 好的测试只验证**外部行为**：给定字段快照与选项状态，产出正确的紧凑数字、时间格式、share text、主题选择结果；不测试 DOM 结构或渲染实现细节。
- 测试模块：数字格式化（万/亿、`--`、千分位）、时间格式化（MM:SS / HH:MM:SS）、字段层级组装（含分P/时间条件出现）、主题选择、首次默认值与上次选择恢复、长链接换行规则、标题行数降级规则（B 主题 19→17→15px）。
- 先例：本项目为从零开始的 userscript，无既有测试；以 `tdd` 逐个 ticket 建立第一个测试模块。
- 视觉验收（海报观感、对比度、二维码安静区）不写单元测试，由 owner 对照原型与导出 PNG 验收。

## Out of Scope

- userscript 运行时行为、数据获取、短链生成、剪贴板/PNG 导出实现（由 idea.md 与后续非视觉 spec 约束）。
- Tampermonkey PNG/组合剪贴板可行性验证（独立技术原型）。
- 二维码真实可扫描性与 b23.tv 跳转保真验证。
- 1:1 社交网格变体、亮/暗页面环境自适应（已按单画布 3:4 定稿，不做变体）。
- C B站亲和主题（已定稿不采用）。
- 生产代码、API adapter、构建配置。

## Further Notes

- 本 spec 的视觉决策来源：`design/prototype.html`（可交互原型，throwaway）与 `design/visual-directions.md`（对比总览与定稿记录）。
- 若后续非视觉 spec 与本文档冲突，以非视觉 spec 的运行时约束为准，视觉系统在其约束内适配。
- spec 中引用的具体尺寸/颜色为排版决策的锚点；实现时以「设计系统语义」（密度、层级、对比度、节奏）为准，允许在保持语义的前提下微调具体像素。
