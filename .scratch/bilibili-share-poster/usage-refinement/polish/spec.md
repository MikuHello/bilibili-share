# B3局部收尾 · 实现规格

Status: approved — 主人批准实现规格及单票安排，工单已发布

Triage: ready-for-agent；仅表示规格可供实施评议，不越过批准门禁。

## Problem Statement

实际视频生成的海报中，二维码白底与封面衍生背景割裂；四等分网格虽让图标起点等距，数字长度不同却导致信息组之间空白不均；扫码说明离二维码偏远，且与左侧统计未形成共同水平行。操作状态提示的句末句号也需去掉。

## Solution

按主人确认的B第二轮局部设计收尾：透明背景深色二维码融入海报，保留扫码静区，不加中心图标；扫码说明靠近二维码并与统计行水平居中对齐。四组“图标＋数字”按实际内容宽度分配一致空白，所有图标尺寸固定，极端数字时整行统一有限缩字。统一交付0.3.1安装脚本。

## User Stories

1. As a 分享者, I want 二维码与背景自然融合, so that 不出现突兀的白色卡片。
2. As a 分享者, I want 二维码保持简洁且可扫描, so that 装饰不影响访问视频。
3. As a 分享者, I want 扫码说明靠近二维码, so that 两者看起来属于同一组。
4. As a 分享者, I want 扫码说明与左侧统计形成共同水平行, so that 信息区整齐协调。
5. As a 分享者, I want 四组信息之间空白一致, so that 不同位数的数字也有均匀节奏。
6. As a 分享者, I want 四个图标固定尺寸且统计始终同排, so that 长标题或数字不会破坏阅读。
7. As a 分享者, I want 必须缩字时四项数字同步调整, so that 不出现同一行字号参差。
8. As a 分享者, I want 缺失、零与极端统计仍准确表达, so that 视觉处理不改变数据含义。
9. As a 分享者, I want 切换分P或时间后二维码保持同样外观, so that 更新不会恢复白底或破坏对齐。
10. As a 分享者, I want 预览和实际PNG一致且目标可扫描, so that 好看的预览可以可靠分享。
11. As a 分享者, I want 简短状态提示不带末尾句号, so that 操作反馈更简洁。
12. As a 维护者, I want 布局基于内容而非某组样例数字, so that 任意视频沿用同一规则。

## Implementation Decisions

- 基线为0.3.0及已提交的状态标点修正；沿用现有领域逻辑、原生DOM及PNG导出，不新增框架或通用布局系统。生产实现重新整理职责，不直接合入原型演示代码。
- 采用B第二轮局部视觉，替代上一规格的二维码白底和四等分统计网格。保持整版构图、标题及信息层级、封面衍生背景、UP独立行、canonical目标等其余已批准规则。
- 二维码使用透明浅色模块、深色码点，无白色卡片、中心图标或覆盖物。沿用四模块静区、原有码图尺寸与纠错级别；初始生成和目标更新使用同一呈现规则。可扫描性优先，若多封面验证发现问题，定位明暗/静区原因，不能静默退回未经确认的新视觉方案。
- 按四个完整信息组的实际宽度分配等量余白，不再保证四个图标起点等距。组内图标与数字间距固定，组间保留最小间距，图标固定54×54导出像素。普通数字沿用36.72px；空间不足时全行共同采用36.72、34、31、28、25px中的最大可容纳字号。复用既有数值格式，不改统计值、不按特定数字写偏移。适配在不可见测量阶段完成，避免可见排版回跳。
- 二维码组和署名/统计组作为一个信息块在既有页脚可用区域居中；扫码说明与54px高的统计行共享水平中心线。去掉码图下方的额外底内边距及说明上外边距，保留码图自身静区。整张预览缩放不改变内部相对布局。
- 仅去掉操作浮层消息末尾中文句号，句中分句标点及重要失败恢复指引保留。已有源码修正随此次安装包发布。
- 保持快照、过期任务拒绝、导出期间一致性和同版本PNG缓存。二维码目标变化继续使对应PNG缓存失效，关闭与导航后不回写。
- 组合复制保持移除，不重新开发；结论明确为通用方案未可靠满足QQ场景，而非所有图文复制方案都不可实现。

## Testing Decisions

- 沿用此前已经批准的领域逻辑与浏览器副作用接缝，不提出新接缝；通过真实生产构建的可见结果和实际PNG验收，不固定私有DOM结构或模拟内部调用链。
- 复用现有B3几何/PNG/扫码、目标一致性、竞态与面板验证。增加主人截图的7969/170/34/313、等宽、混合位数/单位、零/缺失与极端数字，验证组间空白相等、全行字号相同、图标54px、同排且不溢出。
- 覆盖短/长/极长标题、横/方/竖封面、浅深及暖冷真实封面与高对比边界；普通与长分P/时间目标均导出PNG并扫描。不能将单一封面的12次原型扫码推广成生产兼容保证。
- 检查桌面与390/320px预览：扫码说明与统计行中心线一致、二维码与说明更紧凑、信息不碰撞；最终PNG再次人工查看。
- 验证标记更新后二维码不恢复白底、PNG失效并生成新目标；同目标重复导出复用，失败仍可重试。状态提示只改标点，沿用现有反馈稳定性/恢复验证。
- 类型检查、单测、相关浏览器回归及Standards/Spec双轴审阅通过后构建0.3.1，记录版本和SHA-256。主人已反馈实际使用0.3.0，但不将截图视为脚本逐字校验；沿用已知浏览器策略边界，不绕过扩展管理页限制。

## Out of Scope

新增主题、整版重排、信息字号整体放大、二维码中心图标、平台专用剪贴板格式或原生桥接、重新上线组合复制、额外设置项。
