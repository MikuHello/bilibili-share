# 视频荣誉书签与悬浮说明

Status: proposed — 视觉原型已确认；规格、测试接缝与拆票待审阅，未授权生产实现。
Triage: ready-for-agent（规格整理；执行仍受审批状态约束）

## Problem Statement

分享海报与详细文案缺少B站页面上值得关注的荣誉信息，例如每周必看的期数、入站必刷收录或排行榜最高名次。当前部分禁用说明作为常驻段落插入面板，改变内容布局。

## Solution

沿用已确认的0.3.4海报与面板，在封面右上沿和BV/av编号之间添加醒目的暖金书签，只呈现当前视频的B站主荣誉原文。详细普通文案与Markdown在统计行之后另起一行包含同一荣誉；简洁文案不增加荣誉。没有有效荣誉时自然省略，不增加请求或等待。

补充说明与操作反馈通过不参与布局的浮层呈现。灰色时间按钮的禁用原因可悬停查看；操作结果直接浮现。失败时保留已有恢复能力。

## User Stories

1. As a 视频分享者, I want 海报包含视频主荣誉, so that 接收者能发现值得关注的信息。
2. As a 视频分享者, I want 荣誉保留期数、名次和限定文字, so that 信息不被夸大或改写。
3. As a 视频分享者, I want 多项荣誉时只展示B站页面主项, so that 海报保持明确重点。
4. As a 视频分享者, I want 荣誉形成跨过封面上沿的右上书签, so that 它有独立层次。
5. As a 视频分享者, I want 书签文字明显大于最初角标, so that 缩小预览时仍能读到。
6. As a 视频分享者, I want 书签避开BV/av编号和标题, so that 视频身份和主要内容仍清晰。
7. As a 视频分享者, I want PNG与预览呈现同一书签, so that 导出结果符合预期。
8. As a 视频分享者, I want 详细普通文案在统计后包含荣誉, so that 复制文字也保留重要信息。
9. As a Markdown使用者, I want 详细Markdown包含同一荣誉并正确转义, so that 特殊字符不会破坏格式。
10. As a 视频分享者, I want 简洁文案不增加荣誉, so that 简洁分享保持现有形式。
11. As a 视频分享者, I want 无荣誉时省略书签和文案行, so that 不出现占位符或空白行。
12. As a 视频分享者, I want 荣誉字段异常不妨碍其他有效信息分享, so that 可选信息不会拖慢主流程。
13. As a 视频分享者, I want 切换分P或时间不丢失或重取荣誉, so that 操作保持流畅。
14. As a 视频分享者, I want 快速换视频或关闭面板后旧荣誉不回写, so that 不会分享错视频的信息。
15. As a 视频分享者, I want 悬停灰色时间按钮能看到不足1秒的原因, so that 知道当前限制。
16. As a 键盘或触屏使用者, I want 无鼠标也能查看禁用原因, so that 说明可访问。
17. As a 视频分享者, I want 分P无法识别的说明也以浮层呈现, so that 面板不多出常驻段落。
18. As a 视频分享者, I want 复制成功或失败时直接出现反馈, so that 无需猜测操作结果。
19. As a 视频分享者, I want 失败后仍能重试、下载或使用适用的手动复制方式, so that 分享可以继续。
20. As a 视频分享者, I want 提示出现与隐藏不移动面板内容且不挡住操作, so that 可以连续使用。

## Implementation Decisions

- 保留现有TypeScript、原生DOM、二维码与DOM转PNG方案；扩展现有metadata到Generation snapshot、Share poster和Share text的路径，无新服务、权限或独立荣誉请求。
- 荣誉为可选快照信息。复用已有view响应，按已验证的一方前端规则读取honor_reply.honor的首项，仅支持数值语义type 1/2/3；未知首项不扫描后续项。argue_info.argue_type为1或2时省略。有效非空字符串desc作为原文，类型异常、空值或缺失均省略；不以字符串化对象形成标签。
- 上述主项规则对应当前B站前端证据，不是永久接口契约。metadata整体失败仍沿用现有错误流程；“省略荣誉”不意味着可以在缺少必要视频信息时生成海报。
- 所有文本按安全文本方式渲染，Markdown仅增加必要转义，不添加自行编造的荣誉或宣传语。
- 已批准书签A以1080×1440海报为坐标基准：top 116px、right 48px，字体38px、字重600、行高1.3；暖金#f1ce84底、深棕#583b16文字，左侧燕尾口与右下折角。封面上沿为144px、右内边距64.8px，书签跨越该边界并略伸出封面。书签不参与网格排版，不改变海报整体尺寸；不遮挡编号或标题。
- 三个已讨论样例必须完整展示：第389期每周必看、入站必刷98大视频、全站排行榜最高第4名。超过当前样例长度的有效原文通过有界排版适配保持完整与不重叠，不能静默截掉期数或名次；如实现发现无法同时满足，回到具体视觉案例修订。
- 无荣誉时不渲染书签，保持原版布局。书签跟随同一快照进入预览与PNG，沿用导出缓存与过期保护。标记选项不触发重复荣誉网络工作。
- 详细普通文案和详细Markdown均在四项统计行后紧接一行荣誉，后续可选分P/时间、编号、链接保持既有顺序。简洁两种格式均不添加；无荣誉不留空行。
- 不足1秒与分P无法识别等禁用原因从常驻段落改为控件旁浮层；禁用控件本身仍不可执行。提供可聚焦或可点按的说明承载入口，悬停/聚焦/触屏点按均可查看，并在离开、失焦或关闭时合理隐藏。
- 成功/失败结果直接显示浮层，无需再次悬停。沿用现有成功消失、错误保留及恢复机制；恢复动作可位于既有操作区域或需要交互的浮层内。交互浮层必须可点击，非交互提示不截获无关操作。
- 提示不占文档流、不保留空白、不遮挡关键操作，按可见空间避让；原型底部方案切换器不进入生产。保留浅深色、窄屏、Escape、焦点返回、减少动态效果以及关闭/导航后的清理。

## Testing Decisions

- 提议沿用已经批准的数据/领域核心与浏览器副作用边界，不另建架构接缝。规格审阅一并确认此方案。
- 优先通过metadata输入到实际可见分享输出的最高可用接缝验证：有效单项、多项首项选择、未知首项、警示抑制、字段异常、无荣誉；必要的纯文案用例补充两种详细格式、简洁排除、原文与Markdown转义。
- 浏览器使用现有受控网络与真实面板集成先例，验证无额外请求、快照身份与过期保护、详情/标记切换后荣誉稳定，以及关闭后的清理。避免断言私有DOM构建顺序或模块拆分数量。
- 生产预览及实际PNG检查三个原文、无荣誉、长标题、不同封面比例、浅深背景及桌面/390px窄屏；核对书签可读、不遮挡编号、二维码可扫描。原型截图仅作为视觉依据，不替代生产导出验证。
- 通过悬停、键盘与触屏方式检查禁用原因；成功/失败提示前后对比主要内容几何位置，验证无布局位移、恢复动作可用、快速操作及生命周期清理。
- 每票fresh implement、TDD、类型检查与双轴code-review；完成后对统一生产构建执行适当集成及导出验收，不重复开启此前已暂停的接收端剪贴板调查。

## Out of Scope

- 新主题、位置选择器、多个荣誉堆叠、人工编辑荣誉、额外热门榜单抓取、短链或分享目标语义变更。
- 重新设计现有封面/标题/统计/二维码排布，框架迁移或无证据的大范围重构。
- 自动安装、发布、扩大浏览器权限、承诺所有未来B站前端版本均保持同一主标签规则。
- 将原型模拟复制/下载当作生产功能，或直接把原型代码合入生产。
