# Bilibili Share：分享文案模板化与海报职责整理

Status: APPROVED — specification and test interfaces approved by owner

## Problem Statement

开发者希望改变分享文案时只修改模板，不必进入面板或重写生成流程。当前虽然有独立文案生成函数，四种格式仍是固定代码；预览还假设最后一行必定是链接。海报已有生成入口，但默认布局、测量、二维码更新和图片导出职责集中，后续维护容易互相影响。

## Solution

普通文案与 Markdown 分别配置简洁和详细模板，共用视频生成快照、分享目标与变量生成能力。默认模板完整保留现有输出；开发者可集中覆盖任意预设，重新构建即可在实际面板使用。变量与简单条件块支持现有数据范围，未来 GUI 可以复用相同模块。

海报整理为明确的数据准备、默认布局与图片导出职责，继续输出当前默认视觉和尺寸。保持原生 DOM/CSS，不新增设置页面。

## User Stories

1. 作为开发者，我希望普通文案使用模板，以便无需修改面板即可调整措辞。
2. 作为开发者，我希望 Markdown 使用独立模板，以便分别控制链接和强调格式。
3. 作为开发者，我希望两类模板共用变量能力，以便只维护一套视频数据来源。
4. 作为开发者，我希望只覆盖一个预设，以便其余默认行为继续工作。
5. 作为使用者，我希望默认文案保持现状，以便更新后继续原来的复制习惯。
6. 作为使用者，我希望详细信息开关继续作用于两类文案，以便按需输出统计信息。
7. 作为开发者，我希望模板支持标题、UP主、链接、BV/AV、统计、荣誉、分P与时间，以便表达现有内容。
8. 作为开发者，我希望可选信息缺失时整段隐藏，以便不留下无内容的标签。
9. 作为使用者，我希望统计值为零时正常显示，以免被错误当成缺失。
10. 作为开发者，我希望 Markdown 变量中的字符得到正确处理，以便视频标题不会意外改变排版。
11. 作为开发者，我希望变量拼错或语法错误得到明确诊断，以便及时修正配置。
12. 作为使用者，我希望模板错误时仍能复制默认文案，以便分享不中断。
13. 作为开发者，我希望链接可以放在模板任意位置，以便自由组织文字。
14. 作为使用者，我希望文案预览和复制结果一致，以便能确认实际分享内容。
15. 作为使用者，我希望分P与时间选项仍由同一分享目标驱动文案和海报，以免指向不同视频位置。
16. 作为维护者，我希望默认海报布局拥有自己的测量和目标更新逻辑，以便局部维护不会泄漏到面板。
17. 作为使用者，我希望海报预览、PNG 与二维码保持原有结果，以便内部整理不改变使用体验。
18. 作为后续开发者，我希望有变量表、配置示例和错误规则，以便未来设置界面能直接复用模块。

## Implementation Decisions

以下工程细节是基于已确认需求提出的实施方案，随本规格整体审批。

- 项目定名 bilibili-share；保留现有 userscript 安装身份、产物路径和持久化键。本期不引入前端框架。
- 优先扩展既有分享文案生成接口，允许显式传入模板覆盖配置；省略配置时走内置默认预设。渲染能力不依赖 DOM、GM 存储或剪贴板。
- 配置包含普通/Markdown 与简洁/详细四个独立预设，支持部分覆盖。生产面板实际使用集中配置入口，不能只提供无人调用的示例模块。
- 模板支持双大括号变量与简单有值条件块；建议条件语法为 {{#if honor}}内容{{/if}}。不支持嵌套条件、else、循环、表达式、函数执行或任意 HTML。字面模板分隔符需有文档化的转义方式。
- 变量名称明确为 title、uploader、url、bvid、aid、views、likes、coins、favorites、honor、part、timestamp。aid 是数字标识，模板按需添加 av 前缀；统计显示继续使用精确千分位形式。
- 分P与时间变量反映当前分享选项；未启用或不可用时视为缺失。链接变量始终来自统一分享目标，不自行组装 URL。
- 已知变量缺失时，荣誉/分P/时间直接替换为空字符串，统计直接替换为 --；条件块依据原始可用性判断，缺失统计不因显示占位符而成为有值。数值零有效；空白可选文本视为缺失。标题等必要字段仍由现有快照有效性约束负责。
- 条件块移除只移除块内内容，不全局修剪空白或折叠换行；预设通过包含适当换行保证现有输出一致。变量值只替换一次，不把数据中的模板标记再次解析。
- 普通文本原样替换文字；Markdown 转义文本变量中的特殊字符，保留模板作者主动写入的 Markdown。规范分享 URL 保持适用于链接目标的形式，不当作一般标题文字破坏其地址。
- 未知变量与无效语法均产生带预设和位置等上下文的开发者诊断；即使变量位于隐藏条件中也要检查。直接调用模块可捕获错误；面板调用层按受影响的预设回退内置模板，并记录诊断，不拖累另一种格式或海报操作。
- 预览使用生成结果的完整内容，不再把末行默认当链接。若保留链接强调，应使用显式识别的规范链接文本或生成结构，不能改变字符顺序、补写缺失链接或吞掉结尾文字。默认面板视觉保持一致。
- 海报默认布局负责 DOM、测量、封面外观和具体节点更新；图片导出负责编码与缓存。保留现有创建、更新和导出的调用能力，内部拆分不要求插件注册系统或第二套布局。
- 保留异步过期结果保护、目标更新后的缓存失效、字体变化后的重新编码、封面失败时文案可用、播放恢复及导航保护。

## Testing Decisions

- 主要测试入口是现有分享文案生成接口：给定快照、目标、选项和模板，断言完整结果或明确错误；不测试内部函数调用次数与文件拆分方式。
- 沿用现有普通/Markdown 简洁/详细文案测试作为默认兼容证据，补充部分覆盖、变量重复、Unicode、零值、缺失字段、条件块空白、非法语法、未知变量、数据不二次解析、Markdown 字符与 URL 场景。
- 浏览器测试覆盖实际面板使用自定义模板：链接在开头/中间、末尾附加文字、无链接、单行、多行；初次打开和切换选项后，预览文字均与实际复制文本一致。
- 错误模板验证受影响预设回退，另一种文案与海报仍可用。
- 海报通过现有创建/更新/导出入口与交付验证脚本检查默认外观、尺寸、二维码目标、缓存失效和导航竞态。浏览器实际图片结果优先于内部 mock 断言。
- 执行类型检查、行为测试、生产构建及相关浏览器回归；无法执行的真实管理器验证必须明确记录，不能用受控环境通过替代。

## Out of Scope

- 配置 GUI、在线模板编辑器、模板存储/导入导出、模板市场。
- 第二套海报、新视觉设计、通用布局引擎、前端框架迁移。
- GitHub 建仓、发布、改远端地址；删除或迁移旧 worktree。
- 重命名现有安装身份、构建产物或偏好键。
